# postgresql-event-log

The new PostgreSQL event store engine ("event log"), built beside `components/postgresql-event-store`, which it must
not change. **Preview in 0.61.0**: published, off by default in the starter, and its API may change in a minor release.

- Reference for the engine as built: `docs/design/event-log.md` (storage, append, tail reader, probe clock, subscriptions,
  leases, wake-ups, invariants, the phase-10 gate). Consumer doc: `LLM/LLM-postgresql-event-log.md`. The bullets below are
  per phase unit; the phase docs they cite are archived under `docs/archive/`.
- `EventLogSchemaContributor.scriptOnly()`: for a harness that only writes a script (schema mode `emit`). An aggregate
  type's two tables then go to the harness' sink, into the emitted script, instead of being created directly on the
  database when the harness does not create the schema. Without it, a type registered before or after `attach` is
  created on the database in every mode but `create`, which in `emit` writes to a database meant to be left alone. Call
  it before the harness runs; the starter does so in `emit`.

- Plan: `docs/archive/event-store-subscription-redesign.md`. Phase-2 design and decisions: `docs/archive/event-store-engine-phase2.md` (§5 overrides any "Proposed").
- Package `dk.trustworks.essentials.components.eventlog`; tables prefixed `el_`.
- Raw pgjdbc only. No JDBI, Reactor, Jackson or `postgresql-event-store` — `architecture/DependencyRulesTest` enforces it. Payloads are opaque JSON text, bound as `text[]` and cast to `json`, so bytes round-trip exactly.
- DDL text lives only in `EventLogSchemaContributor` (the schema harness rule, `SchemaRulesTest`); `EventLogSchema` runs it under the bootstrap lock when the component owns its schema. All other SQL lives in `EventLogStorage`. Every derived name goes through `AggregateTypeTables` (validated, never truncated).
- Appends run on the caller's `Connection` and never commit. Every append statement takes `pg_current_xact_id()` first (I4, decision 4) — do not remove the `xid` CTE because the head write happens to assign one too. `EventLogAppendXidWindowIT` guards it.
- Event types are interned in their own committed transaction on the engine's `DataSource`, cached only after commit (decision 2).
- Start-up refuses a database where `backend_xid` of another backend is invisible, and an event table whose `global_order` identity cache is not 1.
- Subscriptions (phase 3, `docs/archive/event-store-engine-phase3.md`): `ReaderLoop` = one platform thread + one held connection per `EventLog`, a `TailReader` per active type (starts at head, F4), attach/detach only at the quiescent point (request queue), never waits on an inbox (overflow → close + detach), read failure → every attached inbox closed `READER_RESTART`. `TailReader` keeps phase 2's logic (probe, holes, F1/F2) but no connection; a type's reader uses the seams/relation of the subscription that activated it. `Subscription` (was `FreshSubscription`) = virtual delivery thread, no held connection: catch-up `(P, W]` → WaitingForWatermark → attach → bridge `(P, C]` (attach holes re-read per page) → attached; `HandledSet` (P + runs) dedupes, resume = `P + 1` from received watermarks only. `Inbox` bound counts events, empty inbox accepts any batch. `ProgressStore` (`el_progress`, reset-epoch CAS, no lease). Every reader/bridge statement re-reads holes as a `UNION ALL` branch, never `OR`; `EventLogGenericPlanIT` checks every `TailStatements` generic plan.
- Tests reach the reader via package-private `EventLog.reader(type)`; `AbstractSubscriptionIT.terminateReaderBackend()` forces a reader restart. Never block the loop thread forever in a hook: it is shared, so the next subscription would never start.
- Phase-0 mutants live in `WatermarkMutant`, settable only through package-private `TestSeams`; every invariant IT (I1-I3, I9, I11) and every phase-3 rule IT (attach, detach, reader restart) has a `must_fail_*` test per mutant, caught through hooks and latches, not sleeps. Reader-side mutants and hooks go on a type's first subscription. Never add a public way to set them.
- Tests: `*IT` use `EssentialsTestContainers.postgres()` (static container); unit tests `*Test`.
- Phase 4 unit A (`docs/archive/event-store-engine-phase4.md`): `Subscription` runs a consistency mode (`FRESH`, `CONTIGUOUS`) and a progress model (`PERIODIC`, `IN_HANDLER_TRANSACTION`) as independent strategies. `CONTIGUOUS`: `A` (derived: everything in `(A, R]` is pending), `R` (received prefix), `HeldBack` above it; release only at the *received* watermark; deferred bridge `(R, min(W_rcv, C)]`; detach keeps pending; its inbox counts an event until `release(n)`. In-transaction pages: connection from the engine's `DataSource`, handler gets `GuardedConnection`, progress update last with reset-epoch and `resume_from = expected` guards; detach acts only between pages. `FRESH` bridge starts at the highest handled order and re-reads `HandledSet.gaps` (fallback to `P` above `holeRangeThreshold`). Crash ITs throw `TestSeams.Crash` from a hook, then terminate `openPageConnection()`'s backend.
- Phase 4 unit B (§4): failures are classified (`Subscription.isEngineFailure`). The engine's I/O (anything thrown outside the handler, or the page connection invalid) retries the same page indefinitely with a doubling backoff, no shrink, no attempt. A handler failure shrinks the page (`StepDown`: halve, keep the size inside the suspect range, double above it), then retries the event alone `retryAttempts` times, then parks it; `ParkEventException` parks at once. What the handler throws on a live connection is a handler failure even when I/O-classified (SQLState `08*`, `SQLTransientConnectionException`; mutant `HANDLER_IO_RETRIED_FOREVER`, `SubscriptionFailureClassificationTest`); a periodic handler holds no engine connection, so everything it throws is its own. In-transaction park rows go in the page transaction that moves past them; periodic ones in autocommit before the event counts as handled; always `ON CONFLICT DO NOTHING`. `ParkedEvents` holds the aggregate of a parked head: its later events are parked `blocked_by` the head; the held set is loaded at start and after a reposition; `retryParked`/`discardParked` (package-private, futures) run on the delivery thread between pages; `EventLog.reset` (package-private) bumps the epoch and deletes the parked rows in one transaction. ITs: `EventLogPageFailureIT` (I14), `EventLogParkedAggregateIT`.
- Phase 5 unit A (`docs/archive/event-store-engine-phase5.md` §1-§5, §7): `EventTypeFilter` (public, temporary; `all()` keeps every phase-4 path) is applied in SQL on catch-up, the `CONTIGUOUS` deferred bridge and both `FRESH` bridge branches, and in memory on attached batches (non-matching rows count as handled; the inbox counts matching rows only, a zero-match batch becomes watermark-only). A short filtered page advances to its read's ceiling `min(W, lower + window)` (`CatchUpWindow`: double on short, quarter on `57014`, density switch to `event_type + 0`); type ids are resolved after the ceiling (`EventTypeRegistry.knownIdOf`, never registers). A filtered `FRESH` bridge page marks `(lower, ceiling]` handled minus the attach holes (`HandledSet.addRange`). `CatchUpPermits`: one fair semaphore per database per JVM, taken per catch-up/skip-ahead/bridge/deferred-bridge statement before `getConnection()`, released before rows are applied. `EventTypeIndex` builds the opt-in `(event_type, global_order)` index `CONCURRENTLY` in the background only when the engine creates the schema (DDL text in `EventLogSchemaContributor.eventTypeIndexStatements`), else logs the statement; validity from `pg_index` only gates the skip-ahead probe. ITs: `EventLogFilteredCatchUpIT`, `EventLogFilteredAttachedIT`, `EventLogCatchUpCapIT` (deterministic via the scan-hold view), `EventLogEventTypeIndexIT`.
- Phase 5 unit B (§6.3, decision 2): a `FRESH` subscription that has waited one backstop interval under an unknown watermark attaches anyway (`ReaderLoop.attach(..., unknownAllowed)`, reply watermark `Long.MIN_VALUE`, `unknownWatermark`), bridges `(P, C]` without raising `W_rcv` (a filtered bridge marks no covered range there: a held value is no attach hole), then hands every unhandled order of `(P, C]` to the loop (`handOff`, quiescent point): `TailReader.handOff` keeps the ones at or below the initial candidate's head as holes of that candidate (disjoint from existing holes/ranges), or answers `FINAL` if it retired. The subscription then re-reads the gaps once before taking any batch (I2 and the retired case; mutant `NO_REREAD_AFTER_HAND_OFF`). More than `holeRangeThreshold` gaps → detach `TOO_MANY_GAPS` and F4's wait until the watermark is known. `CONTIGUOUS` keeps F4's wait. ITs: `EventLogGapHandOffIT`, `EventLogFilteredCatchUpIT` (restarted reader).
- Phase 6 unit A (`docs/archive/event-store-engine-phase6.md` §2, §4, §5; §9 decision 2): a wake sets `ActiveType.wake` (an `AtomicBoolean`, no request) and unparks the loop; the loop takes every flag with `getAndSet(false)` *before* it reads. A single due type is read alone with the combined probe (`probe`/`probeWithRanges`, kept) when it wants a running set and the probe clock allows, else with `plainTail`/`rereadTail`; two or more (at most `MAX_FLUSH_TYPES`) go in one pgjdbc flush of tail statements with exactly one `SELECT RUNNING_SET`, last (I11: the flush shares one implicit transaction, where backend status is cached). Two clocks: a wake makes the tail due now; a running set waits `wokenProbeWait` (cost rule, floor `wokenProbeMin`) after a wake, else `probeWait`. Phase 10 gate: while a hole, range or candidate is outstanding (`TailReader.holesWaiting`) either wait is capped at `EventLogSettings.holeProbeWaitMax` (default 100 ms), so the cost rule's ~1 % probe budget is a soft target then (`ReaderLoop.probeWait`, mutant `HOLE_PROBE_WAIT_UNCAPPED`, `ProbeCostTest`). A wake moves no reader state. Tier 2 = public temporary `EventLog.afterCommit(...)` and package-private `EventLogCommitCallback` (foundation's `UnitOfWorkLifecycleCallback`). No thread, no connection added. ITs: `EventLogWakeBeforeCommitIT` (3-type flush with the scan hold in the middle type), `EventLogWakeIT`, `EventLogProgressIT` (I7, tier 2 lost), `EventLogCommitCallbackIT`.
- Phase 6 unit B (§3, §6.1, §6.3; §9 decision 1): tier 1, on with `EventLogSettings.crossJvmWakeUp` (default `true`). `WakeNotifier` (one per `EventLog`, virtual thread from the first `afterCommit` of a registered type, parked when idle) coalesces committed types in a set and sends one `SELECT pg_notify(?, p) FROM unnest(?::text[]) p` (channel `el_wake`, payload `<instance>:<type>`, instance = 8 random chars) on a borrowed connection; a failed send is dropped. `WakeListener` (one per `EventLog`, platform thread `eventlog-listener` + one held connection with `application_name = eventlog-listener`) runs only while the reader loop has an active type (`ReaderLoop.onActivity`); drains with P0.17's `PINNED_PEEK` (reflective pin of `PGStream.nextStreamAvailableCheckTime`, undone before release; `WakeTierTest` guards the field names), `QUERY_POLL` (1 ms doubling to 50 ms) if the pin fails; drops its own instance's notifications, only sets wake flags; on failure waits `min(backstop, 1 s)`, reconnects, re-runs `LISTEN`, then `wakeAll()`. Stop = `UNLISTEN *` + application name reset; the notifier's kick (`<instance>:`, no type) ends its blocking read at once. Mutants and hooks of both go on the package-private `EventLog.wakeSeams(TestSeams)`; test knobs are package-private fields (`channelForTests`, `deafForTests`, `reconnectDelayForTests`, `queryPollForTests`). No observer methods were added (counts are package-private fields). ITs: `EventLogWakeListenerIT`, `EventLogProgressIT` (I7 arms listener killed, `NOTIFY` lost).
- Phase 6 unit D (§10.8, coalescing; defaults `wokenReadMin` 0 = off, `notifySendMin` 2 ms): `EventLogSettings.wokenReadMin` - a woken read starts no sooner than that after the start of the type's last read of any kind (`ReaderLoop.wokenReadDueNanos`): the wake lowers `nextDueNanos` to that time and `ActiveType.wakePending` carries it to the read; it is deferred, never dropped, and never pushed past the due time the type already had (backstop, I7). `notifySendMin` - the notifier starts a send no sooner than that after its previous one; types added meanwhile stay in the set and go out together; `stop` sends at once. Zero turns either off. Mutants `WOKEN_READ_DROPPED_INSIDE_INTERVAL` (loop) and `NOTIFY_DROPPED_INSIDE_INTERVAL` (wake seams); IT `EventLogCoalescingIT` (300 ms intervals, backstop 30 s).
- Phase 7 unit A (`docs/archive/event-store-engine-phase7.md` §2-§8, decided §14): exclusive subscriptions on engine leases, no `FencedLockManager`. Public temporary `EventLog.subscribeExclusive(...)` (periodic `Handler`, in-transaction `PageHandler`) keys the row `(subscriber, aggregate_type, '')` with `exclusive = true`; a non-exclusive `SubscriptionSpec` needs a non-blank instance name, and `PROGRESS_START` no longer rewrites `exclusive` (a mismatch refuses to start). `LeaseKeeper` (one per `EventLog`, virtual thread `eventlog-lease` while an exclusive subscription exists, one borrowed connection per pass every `leaseRenewalInterval`) sends one `LEASE_RENEW` for all owned leases (keyed by fence and owner, confirmed at the time it was *sent*) and one `LEASE_CLAIM` for all standbys (`LEASE_CLAIM_NEW` inserts a row never seen); fences only from `el_lease_fence_seq` inside the claim; owner = `[nodeName/]instance`. `Lease` (`STANDBY`/`OWNED`/`SUSPENDED`/`LOST`) is written by the keeper; the delivery thread checks the local deadline (`confirmedAt + leaseLocalStop`) before every periodic handler call, save and park, and before a page borrows and commits; past it, it suspends until a renewal confirms again. A loss (`LeaseLostException`) leaves the reader and goes standby; nothing is saved. Every write binds `FENCE_GUARD` (epoch + fence + owner; null fence for non-exclusive); the periodic park insert and `failedAgain` are guarded by a `FOR SHARE` CTE on the progress row (phase-4 §11.5 gap closed for every subscription). §2.6's zero-row table is `Subscription.decide`: exclusive row gone → stop with an error. `stop()` releases in one statement (`PROGRESS_SAVE_RELEASE` periodic, `LEASE_RELEASE` in-transaction). Exclusive pages `set_config('idle_in_transaction_session_timeout', leaseDuration, true)`. Keeper mutants/hooks via package-private `EventLog.leaseSeams(TestSeams)`; delivery-side ones on the subscription's seams; most mutants bind a null epoch/fence/owner into the `coalesce` guard. Unit B owns the gate ITs.
- Phase 7 unit B (§9): gate ITs on `AbstractLeaseIT` (test lease timings, `Gate` latches on keeper/delivery hooks, the test-only progress log trigger `el_test_progress_log`, `@AfterEach` terminates leftover backends): `EventLogLeaseFencingIT` (I5), `EventLogResetRaceIT` (I6, each arm non-exclusive and exclusive), `EventLogLeaseIT` (I16), `EventLogTakeoverIT` (in-JVM). `EventLogForkedTakeoverIT` + `LeaseOwnerProcess` (child JVM) are opt-in: `-Dspike.run=true`. Run any IT against another major with `-Deventlog.it.image=postgres:16.15` (`AbstractEventLogIT`). The in-transaction fencing arms also switch off the expected-value guard (`PROGRESS_WITHOUT_EXPECTED_RESUME`), which alone would refuse a stale page.
- Phase 7 unit D (§15.5): `LEASE_RENEW` and `LEASE_CLAIM` take the key list as a `MATERIALIZED` CTE `k` that also carries every value the row is checked against (`instance_name`, owner, fence, `exclusive`, claim time), and every condition compares an `el_progress` column with a `k` column. `el_progress` then has no restriction of its own, so its estimate is the table's size whatever the statistics say, and the planner never picks the O(N²) nested loop that rescans the key list (what the pre-unit-D shape got on a never-analysed table under a generic plan). Keep that rule when editing them: a predicate on `p` alone brings the exposure back. `EventLogLeasePlanIT` (custom and generic plans, never-analysed table, with a must-fail control) and `LeaseStatementVariantsTest` (the mutant variants' text replacements still match) guard it.
- Phase 8 unit 8a-A (`docs/archive/event-store-engine-phase8.md` §2, decided §15): the public API is `EventLog.subscribe(SubscriptionDefinition, DeliveryHandler | PeriodicHandler | PageHandler)` and `subscribe(definition, PageHandler, PageTransactionSource)`, returning `SubscriptionHandle` (`status()` = `SubscriptionStatus`, a local snapshot with no statement). The handler kind decides the progress model. `Subscription` is package-private (wrapped by `DefinedSubscription`); tests keep the package-private `subscribe(SubscriptionSpec)` path for seams, and `test/.../Definitions` builds the definitions the removed temporary overloads stood for. `SubscriptionDefinition.errors()` empty = `ErrorSettings.defaults(settings)`; `StepDown`, the retry loop and the I/O backoff read the subscription's `ErrorSettings`. Page transactions go through `PageTransactionSource.OpenPage` (`EnginePageTransactions` is the default); the engine still issues the progress update last on the page's connection and calls exactly one of commit/rollback; a non-engine source is checked against `DATABASE_IDENTITY` at subscribe. `StartFrom.head()` is a sub-select in `progressStart(headTable)` / `leaseClaimNew(headTable)`. `el_progress.filter_digest` (null without a filter) is stored by `PROGRESS_START`, `LEASE_CLAIM_NEW` and `PROGRESS_SET_MODE`; a change warns and is stored, never refused. The tenant filter goes into the spec (`SubscriptionSpec.tenant`); see the 8a tenant bullet. `EventLog.commitCallback()` is public; `afterCommit(Collection)` is permanent. IT: `EventLogSubscriptionApiIT`.
- Phase 8 unit 8a-B (`docs/archive/event-store-engine-phase8.md` §4, §9.3): `EventLog.admin()` returns `EventLogAdmin` (impl `DatabaseEventLogAdmin`, works from the database on any node): `subscriptions(Optional<type>)` is one statement (`ADMIN_SUBSCRIPTIONS`, `LIMIT adminListLimit`; the lag's head is read per listed type through `el_aggregate_types` with `query_to_xml`, so types this JVM never registered show too), `subscription(ProgressKey)`, `parked(key, after, limit)`, `reset(key, from)` and `reset(key, from, Connection)` (the caller's transaction; never commits), `retryParked`/`discardParked` (store `requested` on the head row; served locally at once if this node runs and owns the subscription, else `ACCEPTED`), `deleteRetiredInstance` (per-instance rows only). `el_parked_events.requested`/`requested_at` are read by the **parked check** at the top of `Subscription.serveParkedRequests()`: only while the subscription holds an aggregate, at most once per `EventLogSettings.parkedCheckInterval` (zero = `backstopInterval`). The serve transaction (`releaseParked`) locks the progress row first under `FENCE_GUARD` (`PARKED_SERVE_GUARD`), in the order a reset locks (progress, then parked rows): do not move it after the parked lock, or a reset racing a serve deadlocks. A failed retry clears the request. Mutants `PARKED_CHECK_SKIPPED`, `PARKED_CHECK_ALWAYS`, `SERVE_WITHOUT_EPOCH`, `SERVE_WITHOUT_FENCE` (subscription seams), `RESET_OUTSIDE_CALLER_TRANSACTION` (package-private `EventLog.adminSeams`). IT: `EventLogAdminIT`. An idle subscription notices a reset only at its next save or page.
- Phase 8a tenant filter (`docs/archive/event-store-engine-phase8.md` §15, question 7): `SubscriptionSpec.tenant` (null = every tenant) is applied exactly where the type filter is - in SQL on catch-up, the `CONTIGUOUS` deferred bridge and both `FRESH` bridge branches; in memory on attached batches and in the inbox count (`Subscription.matches`, `Inbox(…, tenant, …)`); no handler wrapper any more. `filtered` = type or tenant filter, `typeFiltered` = type only; type ids are resolved only for a type filter. The filtered statements are `EventLogStorage.FilterStatements`, one set per shape (`TailStatements.typeFilter`/`tenantFilter`/`typeAndTenantFilter`), predicate parameters ids then tenant, bound by `Subscription.bindFilter`; the density switch uses `tenant || ''`; in the bridge's ranges branch the tenant predicate sits behind an `OFFSET 0` fence (a generic plan otherwise walks the table when the statistics think the tenant rare; `EventLogGenericPlanIT` covers every shape). Opt-in `(tenant, global_order)` index `el_<type>_events_tenant_order`: `EventLogSettings.tenantIndexed`, `EventTypeIndex` with `Kind.TENANT` (same build/log/validity rules, DDL in `EventLogSchemaContributor.tenantIndexStatements`); either valid index serving the filter enables the skip-ahead probe. The filter digest already covered the tenant. Mutant `FILTERED_BRIDGE_MARKS_RANGE_UNDER_UNKNOWN_WATERMARK`; IT `EventLogTenantFilterIT` (its warm subscription is `CONTIGUOUS`, so the reader learns of the held event only from the tested subscription's hand-off).
- Phase 8 unit 8b-A (`docs/archive/event-store-engine-phase8.md` §5.2, §14 question 8): the reads the `EventStore` adapter needs, statements in `EventLogStorage.ReadStatements` (generated once per type, `RegisteredAggregateType.reads`): `findLastEvent` (backwards on the stream-order constraint, `LIMIT 1`), `findEvents(ids)` (`= ANY` on the event-id index, global order, missing ids skipped), `loadByGlobalOrder(GlobalOrderRead)` on the caller's connection or a borrowed one (autocommit off, rolled back and returned when the stream closes; the caller must close the `Stream`), `findHighestGlobalOrder`/`findLowestGlobalOrder` (`max`/`min`, `OptionalLong`), `findCausedBy(uuid)` (every registered type, by event table name, each in global order). `GlobalOrderRead` is an inclusive range (`Long.MAX_VALUE` = open) as `LongRange` is; its tenant filter keeps untenanted rows (`tenant IS NULL OR tenant = ?`, the old store's semantics, unlike the subscription tenant filter); type and tenant are nullable-parameter `Filter`s on the primary-key range. Additional orders are a separate statement merged in the JVM (`ResultSetStream.merge`): a `UNION ALL ... ORDER BY` got a generic plan that sorts the whole range before its first row. The causation index is the partial `el_<type>_events_caused_by` (`WHERE caused_by_event_id IS NOT NULL`), created with the event table by `aggregateTypeStatements` (`createIndexUnlessPresent`); not opt-in. Plans: `EventLogGenericPlanIT` (index-only, the specific index each uses, a range without a sort, a must-fail control without the caused-by index); behaviour: `EventLogAdapterReadsIT`.
